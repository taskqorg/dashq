# Official update handoff evidence

Task: https://github.com/taskqorg/dashq/issues/279

D2 requires CoreQ update integrity, offline selftest and normal activation.
A1/A2 were checked in isolated temporary installations, with the official
Linux x86_64 0.18.1 and 0.18.2 assets verified against their release SHA256SUMS.
`python3 scripts/test-update-handoff.py OLD_ASSET_DIR NEW_ASSET_DIR` supplies
release responses through an isolated curl fixture; it never accesses an installed
service. Download each version's linux-x86_64 asset and SHA256SUMS with
`gh release download VERSION --repo taskqorg/dashq --dir DIRECTORY` first.

- Before: actual 0.18.1 updater rejects actual 0.18.2 staged selftest with
  `installation release entrypoint invalid`; current remains 0.18.1.
- Mismatch: CoreQ 0.11 passes SELFTEST_OFFLINE but not INSTALL. CoreQ 0.19.2's
  root resolver rejects staging release directories without an explicit root.
- After: the handoff script supplies the explicit root to that same old updater;
  current becomes 0.18.2 and previous stays 0.18.1. Installed candidate bytes
  equal the released artifact.
- Corrupt checksum: refused before selftest; current remains 0.18.1.
- Valid checksum with an intentionally failing fixture selftest: refused before
  activation; current remains 0.18.1.

This is a compatibility invocation, not a new updater or a change to D2.
Under A3 and R2, official installed update, checksum and bounded report remain
PM-only verification. A375 remains unproved until that live evidence exists.
