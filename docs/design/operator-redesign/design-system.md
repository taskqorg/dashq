# Approved visual direction

Owner accepted the consolidated direction on 2026-10-22: minimal host-first hierarchy, meaningful compact icons, readable text, labelled right-hand trends and few-step detail/action/return journeys. Complete TaskQ interiors remain upstream-owned and unchanged.

## Information model

| Level | Person's question | Content |
|---|---|---|
| Overview | Where should I look? | Recognizable objects and clearly scoped state; consequential exceptions; a direct route into the affected object |
| Object | What is happening here, and what can I do? | Related services/work, the relevant measured values, current reason and permitted next action |
| Evidence | Why should I trust this conclusion? | Timeline, source/time/coverage, exact observations, receipts and technical identifiers |

These are disclosure levels, not three mandatory pages. An object can expand within context. Back restores the original position; refresh must not disturb reading or editing. Every existing capability needs a destination; reducing the overview does not delete it.

## Visual grammar

One object has one recognizable visual group:

**Identity → scoped state → relevant fact → next action.**

- Identity is the strongest text within the object. Related facts stay close to it; unrelated objects have a clear shared boundary or spacing.
- State explains the practical consequence in ordinary language. A measured resource, installation, service, login and task attempt keep their own scope. No umbrella Healthy or Offline label is inferred from activity or a recent sample.
- A fact earns overview space when it changes recognition, a decision or the next action. Versions, receipt IDs and repeated source explanations belong in detail by default; any departure from older approved placement must be explicitly reviewed.
- The action sits with its subject. Selecting the problem opens its explanation and evidence directly. Routine inspection is distinct from a consequential change and its existing review/receipt requirements.
- Show missing critical evidence as a readable state with a nearby observation age. Do not fill a row with separate `?` cells. Unknown still remains explicit wherever a dependent value is presented.
- Ordinary operation stays visually quiet. Exceptions have a clear textual reason and restrained emphasis. Color supports meaning; it does not carry meaning alone.
- Never present several unlabeled version numbers or metrics as a tuple that requires matching against a distant legend.

## Visual foundations

| Area | Candidate |
|---|---|
| Typography | System font; four visible roles: page title, object title, primary content and supporting context. Trial sizes 24/18/16/14 px, scaling with user text preferences; weights 400/500. Shared TaskQ interiors keep parent typography. |
| Spacing | Trial 4 px unit; 8 px within a tightly related group, 16 px between related groups, 24 px between sections. Validate at actual size; do not stretch content to fill width. |
| Alignment | One consistent content edge and repeatable object structure. Use columns only when repeated values actually need comparison. |
| Surfaces | Neutral page and grouped content; subtle separation only where it establishes ownership. No nested cards, decorative gradients or large empty metric tiles. |
| Color/icons | Inherit TaskQ semantic tokens and bundled outline/provider assets. No new palette or icon vocabulary. Keep neutral observations neutral. |
| Quantities | Exact value plus unit. Capacity bars require a known total; trends require real ordered samples and a visible period. Chart and number answer the same question. |
| Controls | Native-looking, clearly named and consistent. Primary and secondary actions are visually distinct; essential actions stay available without hover. |
| Motion | Existing refresh continuity and reduced-motion requirements. No decorative animation in the foundations review. |

Apple's [layout](https://developer.apple.com/design/human-interface-guidelines/layout) and [typography](https://developer.apple.com/design/human-interface-guidelines/typography) are visual research references, not a claim of native Apple conformance. “Apple-like” here is the owner's direction for clarity and restraint, not permission to trade legibility for empty space or remove operational capabilities.
